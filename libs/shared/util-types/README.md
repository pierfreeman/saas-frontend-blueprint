# @org/shared/util-types

Foundation library shared by all `*Api` services and domain libraries. Provides the `API_BASE_URL` injection token and the full OpenAPI-aligned TypeScript type tree.

**Import path**: `@org/shared/util-types`

---

## Exports

| Symbol         | Kind                     | Description                                                 |
| -------------- | ------------------------ | ----------------------------------------------------------- |
| `API_BASE_URL` | `InjectionToken<string>` | Backend base URL token                                      |
| `paths`        | Interface                | Full OpenAPI path map (endpoint → method → operation)       |
| `components`   | Interface                | All schema definitions (`components['schemas'][...]`)       |
| `operations`   | Interface                | All operation signatures (`operations['OperationId'][...]`) |
| `webhooks`     | Interface                | Webhook definitions                                         |
| `$defs`        | Interface                | JSON Schema `$defs`                                         |

## `API_BASE_URL` token

```ts
// src/lib/api-base-url.token.ts
export const API_BASE_URL = new InjectionToken<string>('API_BASE_URL');
```

This token carries the backend API base URL (`http://localhost:3000` in dev, the deployed API URL in prod). It must be provided at two levels:

1. **Shell's `appConfig`** — covers all services instantiated in the shell bundle:

   ```ts
   { provide: API_BASE_URL, useValue: environment.apiUrl }
   ```

2. **Each remote's route group `providers`** — required because each MFE is a separate Webpack bundle with its own `InjectionToken` instance. Without re-providing, `inject(API_BASE_URL)` in the remote's services resolves to a different token instance (from a different bundle) and throws `NullInjectorError`.

## OpenAPI types (`openapi.types.ts`)

Auto-generated by [`openapi-typescript`](https://github.com/drwpow/openapi-typescript) from the backend's `swagger.json`. Contains 3191 lines covering all endpoints, request bodies, and response shapes.

> **Do not edit manually.** Regenerate from the backend OpenAPI doc when the API changes.

### How to regenerate

```sh
# From the nx-angular workspace root, pointing at the running backend
npx openapi-typescript http://localhost:3000/swagger-json -o libs/shared/util-types/src/lib/openapi.types.ts
# or from a local file
npx openapi-typescript ../saas-backend-blueprint/swagger.json -o libs/shared/util-types/src/lib/openapi.types.ts
```

### Using the types

Domain libs extract specific types via type aliases to keep import paths clean:

```ts
// In a domain lib (e.g. billing.api.types.ts)
import type { components } from '@org/shared/util-types';

export type SubscriptionResponse =
  components['schemas']['SubscriptionResponseDto'];
```

```ts
// For operation-based types (request/response from a specific endpoint)
import type { operations } from '@org/shared/util-types';

export type User =
  operations['AuthController_getMe']['responses']['200']['content']['application/json'];
```

```
src/lib/

src/index.ts              — public exports
```

---

## Design notes

- All types are consumed as `import type` — no runtime cost
- Domain libs own their type alias files (`<domain>.api.types.ts`); consumers import from the domain lib, not from `@org/shared/util-types` directly
- `API_BASE_URL` is the only runtime export from this lib; everything else is type-only
